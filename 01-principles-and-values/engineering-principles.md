# Engineering Principles

Core values that guide how we build technology at Better.sg.

## Our Mission

### Tech for Good 🌟
Better.sg exists to use technology as a driver of positive change and progress social causes in Singapore. Every line of code we write should serve this mission.

**What this means:**
- Build with purpose and social impact in mind
- Focus on solving real problems affecting communities
- Create tools that empower non-profits and social organizations
- Design solutions accessible to all, regardless of technical expertise

**Examples:**
- Mental wellness chatbots for caregivers
- Misinformation detection tools (checkMate)
- Community resource platforms (Schemes SG)
- Educational matching platforms for underserved students

## Core Technical Principles

### 1. Open Source First 📖

**Principle:** All Better.sg projects are open source and free to use.

**Why it matters:**
- Transparency builds trust with communities we serve
- Others can learn from and improve our work
- Maximizes reach and impact of our solutions
- Enables community contributions and collaboration

**In practice:**
- Use permissive licenses (MIT, Apache 2.0)
- Document everything clearly for external contributors
- Make code readable and maintainable
- Share learnings and best practices publicly

### 2. Security & Privacy First 🔐

**Principle:** Protect user data always. No exceptions. This is non-negotiable.

**Why it matters:**
- We often work with vulnerable communities
- Trust is essential for social impact work
- Privacy breaches can cause real harm
- We set the standard for tech-for-good projects

**In practice:**
- Never store sensitive data unnecessarily
- Use encryption for data at rest and in transit
- Follow PDPA and data protection regulations
- Regular security audits and vulnerability scanning
- Principle of least privilege for all access

### 3. Accessible by Design ♿

**Principle:** Technology should be accessible to everyone, regardless of ability or technical skill.

**Why it matters:**
- Social impact work must include marginalized communities
- Many non-profits serve users with varying abilities
- Accessibility is a right, not a feature

**In practice:**
- Follow WCAG 2.1 AA standards minimum
- Test with screen readers and assistive technologies
- Use semantic HTML and ARIA labels
- Support keyboard navigation
- Provide clear error messages and help text
- Design for low-bandwidth and older devices

### 4. Quality Over Speed 🎯

**Principle:** Ship working code and improve iteratively. Don't let perfect be the enemy of good.

**Why it matters:**
- Our users depend on reliable tools
- Technical debt slows down volunteer progress
- Quality code is easier for volunteers to contribute to

**In practice:**
- Write tests for critical functionality
- Use linting and code formatters
- Follow established coding standards
- Review all changes before merging
- Refactor as you go, not later

### 5. Document as You Go 📚

**Principle:** Help your teammates and your future self. Documentation is part of the work.

**Why it matters:**
- Volunteers come and go - knowledge must persist
- New contributors need clear onboarding
- Good docs reduce maintenance burden
- Documentation is accessibility for developers

**In practice:**
- Write clear README files
- Comment complex logic
- Maintain up-to-date API documentation
- Create runbooks for deployment and ops
- Document architectural decisions (ADRs)

### 6. Fail Fast, Learn Faster 🚀

**Principle:** Experiment boldly. Recover quickly. Share what you learn.

**Why it matters:**
- Innovation requires risk-taking
- Early failures prevent bigger problems
- Shared learning accelerates the community

**In practice:**
- Use feature flags for new functionality
- Implement proper monitoring and alerting
- Conduct blameless post-mortems
- Share lessons learned publicly
- Prototype before committing to architecture

## Community Values

### Volunteer-Friendly 🤝

**Principle:** Async-first, inclusive, respectful of time. We value your contributions.

**What this means:**
- Recognize volunteers have other commitments
- Support flexible contribution schedules
- No expectation of 24/7 availability
- Value quality over quantity of contributions

**In practice:**
- Async communication via Slack/GitHub
- Clear documentation so anyone can pick up work
- No meetings unless absolutely necessary
- Respect timezone differences
- Celebrate all contributions, big and small

### Inclusive & Collaborative 🌈

**Principle:** Welcome contributors from all backgrounds. Build together, not alone.

**What this means:**
- Diverse perspectives create better solutions
- Everyone has something valuable to contribute
- We learn from each other

**In practice:**
- Use inclusive language in code and docs
- Provide mentorship for new contributors
- Be patient with questions
- Give constructive, kind feedback
- Recognize different experience levels

### Impact-Driven 📊

**Principle:** Measure what matters. Build for real users and real needs.

**What this means:**
- Start with user research and problem validation
- Define success metrics upfront
- Gather feedback early and often
- Be willing to pivot based on evidence

**In practice:**
- Talk to actual users before building
- Use analytics to understand usage patterns
- Conduct user testing sessions
- Track impact metrics, not just technical metrics
- Sunset projects that don't deliver value

---

## Remember

These principles aren't rules - they're guidelines informed by Better.sg's mission and values. When in doubt:

1. **Put users first** - Especially vulnerable communities
2. **Be kind** - To users, teammates, and yourself
3. **Stay curious** - Keep learning and sharing
4. **Make impact** - Every contribution matters

**Together, we're building a better Singapore through technology. 🇸🇬**
